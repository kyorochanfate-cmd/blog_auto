# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Flask web app deployed on Google Cloud Run that lets a single user manage multiple Hatena blogs. Each blog is configured in Firestore; the app generates articles via Gemini and posts them via Hatena AtomPub. Built to run from a smartphone — UI is mobile-first.

## Common commands

**Deploy (the main command — used constantly):**
```bash
gcloud run deploy gadget-blog --source . --region=asia-northeast1 --project=blog-auto-tool-87676 --timeout=3600 --memory=1Gi
```
Re-running this is the standard development loop. Cloud Build picks up source changes and ships a new revision.
The `--timeout=3600` is required for the auto-run pipeline (10 articles × ~30-60s each can exceed default 300s).

**Tail logs:**
```bash
gcloud run services logs tail gadget-blog --region asia-northeast1
```

**Local dev:**
```bash
python -m flask --app webapp.app run --host 0.0.0.0 --port 8080
```
Local runs still hit production Firestore — there's no local DB.

There are no tests, no linter, no build step beyond Cloud Build's Dockerfile.

## Architecture: the 4-lever design

Every blog's behavior is controlled by 4 user-editable settings stored in Firestore (collection `blogs`). Treat these as the system's primary contract — when adding features, ask which lever they belong to:

1. **`genre`** — Google News keyword. Used only when topic_policy is empty.
2. **`topic_policy`** — Free-text instruction telling Gemini what kind of topic to generate. **If set, news collection is skipped entirely.** This is the key branch in `webapp/app.py:generate_topics()`.
3. **`article_policy`** — Free-text instruction injected as `【★最優先ルール★】` at the **very top** of `ARTICLE_PROMPT`. Order matters: this section must precede the persona/default rules or Gemini ignores it.
4. **`tone_prompt`** — Voice/character instructions.

Plus three optional flags: `use_charts`, `use_wiki_images`, `amazon_affiliate_tag`.

## Two distinct generation flows

**News-based** (`topic_policy` empty): RSS/Google News collection → `select_top_topics()` clusters → user picks → `fetch_article_texts()` scrapes article bodies → `generate_article()`.

**Policy-based** (`topic_policy` set): No RSS at all. `generate_policy_topics()` asks Gemini to invent topics from the policy alone → user picks → `generate_article()` runs with a stub source telling Gemini "use your own knowledge."

When the stock blog is in policy-mode, `topic_selector.py:_random_stock_hint()` is injected if the policy contains "ランダム" — Python pre-picks a TSE sector and code range to counter Gemini's bias toward famous companies. This randomness must happen Python-side; asking Gemini for "random" returns Toyota/Sony every time.

## Prompt construction in `article_generator.py`

`ARTICLE_PROMPT` uses `str.replace()`, **not** `str.format()`. Scraped article text frequently contains `{...}` (JSON, code blocks) which crashes `.format()`. Keep this convention.

Section order in the prompt matters:
```
{policy_section} ← article_policy (highest priority)
{tone_section}
{extra_section}
{persona_intro} + default rules
{wiki_images_section}
{chart_section}
{amazon_section}
```

Adding a new optional section means: define a constant, plumb a parameter through `generate_article()`, add a `.replace()` call, and put a `{xxx_section}` placeholder in `ARTICLE_PROMPT`.

## Chart and image features

**Charts** (`use_charts=True`): Gemini emits `[CHART type="bar" title="..." labels="..." values="..." unit="億円"]` markers in markdown. `_convert_chart_markers()` regex-replaces them with QuickChart.io image URLs. Unit goes on Y-axis title (bar/line) or chart title (pie).

**Wiki images** (`use_wiki_images=True`): `src/image_finder.py` queries Wikimedia Commons API. License filter in `_is_commercially_usable()` excludes anything containing `nc` (non-commercial) and only allows CC0 / CC BY / CC BY-SA / Public Domain. **Don't loosen this filter** — the user is monetizing.

**Amazon links**: Use search URLs (`/s?k=...`), not `/dp/ASIN/`. Gemini hallucinates ASINs, so direct product links 404. `_apply_amazon_affiliate()` appends `&tag=` to all `amazon.co.jp` URLs.

## Auth

Google Sign-In (GSI) only — no password auth. `webapp/google_auth.py` verifies ID tokens; `config.ALLOWED_EMAILS` allowlist gates access. Sessions are signed with `FLASK_SECRET_KEY`.

## Firestore schema

- `blogs/{id}` — one doc per blog with the 4 levers + Hatena credentials + flags + auto-publish settings.
- `posted_links/{hash}` — records source URLs already used in published articles, to dedupe future topic selection. ID is `sha256(blog_id:url)[:32]`.
- `published_articles/{hash}` — record of every published article (title, url, keywords) for internal-link suggestions.
- `pending_reviews/{hash}` — articles auto-generated by the cron run but blocked by the compliance check. UI at `/pending` lets the user approve or discard.

`webapp/blogs.py:_normalize()` is the single source of truth for which fields exist on a blog doc. New fields go here.

## Auto-publish pipeline

`src/auto_runner.py` runs the full flow headlessly. Triggered by Cloud Scheduler hitting `/auto-run/<blog_id>` (or `/auto-run` for all enabled blogs).

Flow per blog: topic selection → article generation → quality auto-improve (if score < 65) → image rehost → **compliance self-check** → publish OR draft to `pending_reviews`. Email digest sent only when something needs attention.

**Compliance self-check (`src/compliance.py`) is the safety layer that lets us remove human-in-the-loop.** Hard-blocks (BLOCK) prevent publish and queue the article for review:
- Plagiarism: ≥3 verbatim 20-char fragments shared with any single source = block. ≥1 = warn.
- Broken images: any external `![](url)` that fails HEAD/GET = block.
- Missing attribution on Wikimedia images (CC BY-SA requires credit) = block.
- Empty title or <800 char body = block (generation failure).

When loosening rules, remember: there's no human review by default. The user only sees compliance failures via Gmail. Don't make BLOCK leak false negatives.

**Cloud Scheduler setup** (per-blog jobs are recommended; one job per blog stays well within Cloud Run timeout):
```bash
gcloud scheduler jobs create http auto-run-<blog-id> \
  --schedule="0 7 * * *" --time-zone="Asia/Tokyo" \
  --uri="https://<cloud-run-url>/auto-run/<blog-id>" \
  --http-method=POST \
  --headers="Authorization=Bearer <AUTO_RUN_TOKEN>" \
  --location=asia-northeast1
```
Set `AUTO_RUN_TOKEN` env var on Cloud Run to the same shared secret. Without it the endpoint returns 401.

**Notification** (`src/notifier.py`) uses Gmail SMTP — needs an app password from https://myaccount.google.com/apppasswords. Set `NOTIFY_EMAIL`, `NOTIFY_GMAIL_ADDRESS`, `NOTIFY_GMAIL_APP_PASSWORD`. Digest is sent only when there's something to review (no spam on clean runs).

## Things that have bitten us before

- `response_mime_type='application/json'` on Gemini calls causes hangs with some models. Don't add it back; parse JSON manually after stripping code fences.
- Google Search Grounding on `generate_content()` silently upgrades to a heavier model and burns API quota. Removed deliberately.
- `str.format()` on prompts with scraped content blows up on `{`. Use `.replace()`.
- Hardcoded UI strings ("ホットなトピック", "商品名") leaked the gadget-only origin. Templates now branch on `b.topic_policy` / `policy_mode`. When adding UI text, keep it genre-neutral.
- Cloud Run default timeout (300s) is too short for the auto-run pipeline (10 articles × 30-60s each). Always deploy with `--timeout=3600`.
- Compliance plagiarism check operates on character-level n-grams (Japanese-safe — no tokenizer needed). If you add multilingual sources, the same algorithm works as-is. Don't replace with word-tokenized variants without verifying on Japanese text.
